# AI 與模型

助手的能力取決於背後的模型，因此 Powerduck 不會把你鎖定在某一家。你選擇並配置模型，應用程式透過安全的本機路徑呼叫它，每項變更仍走同樣的可審閱卡片。

## 自帶模型

在設定中針對任何**相容 OpenAI** 的 Chat Completions 端點配置助手：

- 選擇內建的服務商預設，或定義一個**自訂**服務商；
- 提供顯示名稱、基礎 URL、API 密鑰和模型 ID；
- 可以配置並選擇多個設定檔。

應用程式不會假設模型來自某個特定服務商。自託管或第三方的相容 OpenAI 端點以相同方式工作，這對有自己模型策略的團隊很重要。

## 進階能力與優雅回退

每個設定檔都有一個**進階能力**選項，預設開啟：

- 開啟時，應用程式使用模型的**原生函式呼叫**，透過網路發送工具目錄，讓模型可以直接選擇並呼叫合適的工具；
- 如果某個端點拒絕原生工具參數——例如不支援工具的較小模型——該端點會被記住，請求會透過**基於內容的回退協定**重試一次。

目標是始終回傳結果：能力強的模型走精確的原生路徑，不支援工具的模型降級到更簡單的協定，而不是讓這一輪失敗。對於應始終使用基礎路徑的設定檔，你可以關閉進階能力。

工具驅動的工作也有邊界：代理執行有限數量的工具輪次（預設三輪）並對呼叫去重，因此工具從不會在迴圈中被執行兩次。

## 為什麼請求要經過主程序

在桌面用戶端，補全請求從 **Node 主程序**發出，而不是網頁檢視。這有兩個具體好處：

- **沒有瀏覽器 CORS 牆。** 適用於網頁的跨域限制不會阻擋對模型端點的呼叫；
- **提示詞和密鑰遠離瀏覽器主控台。** 請求 URL、授權頭、系統提示詞和工具清單在渲染層網路面板中不可見。

閘道被刻意約束，而不是充當開放代理：

- 校驗目標（回環位址和允許的主機），清洗請求頭，並防止透過回應頭進行的回應拆分；
- 請求可以取消（`ai:cancel`）。

## 桌面與 Web

同一個助手在兩種執行環境中都能工作，使用各自適配的通道：

- **桌面（Electron）：** 能力在本機引入並執行，補全請求透過主程序代理；
- **Web：** 同樣的工作流透過 HTTP 執行，呼叫服務 API 而非本機模組。

這正是應用程式在 Electron 路徑之外保留 Web 相容路徑的原因：意圖處理和卡片表現一致，只是傳輸方式隨執行環境改變。

## 意圖如何被識別

意圖不是透過為每個功能列舉關鍵詞來處理的。應用程式改為向模型呈現一個明確、描述清晰的**工具目錄**——每個工具的 ID、參數以及應在何種確切情形下使用。模型從目錄中選擇最佳工具，確定性宿主校驗並執行它，寫入動作要求確認。

因此增加一個能力意味著向目錄新增一個工具（並準確描述它），而不是維護更長的關鍵詞清單。同一個目錄還可以透過 MCP 伺服器與外部代理共享，讓能力在產品和其他工具之間保持對齊。

## 隱私姿態

- 在桌面端，你的 API 密鑰和提示詞保留在本機，不暴露給渲染層；
- 是確定性宿主——而非模型——校驗並套用每項變更；
- 每次寫入在執行前都由你核准。
