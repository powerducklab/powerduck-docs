# 로컬 모크 서버

모크 서버는 스펙에서 직접 API의 동작하는 스탠드를 제공해 백엔드 준비 전에 프런트엔드와 클라이언트 작업을 진행할 수 있습니다. 외부 인프라를 세울 필요도 없습니다. 데스크톱 메인 프로세스에서 실행됩니다.

## 모크 시작

모크 서버 모드에서 또는 AI 채팅에서 직접 시작할 수 있습니다. 채팅에서 시작하면 앱이 서비스 주소를 확인합니다.

다음 옵션이 있습니다.

| 옵션 | 범위/형태 | 용도 |
|---|---|---|
| `port` | 정수 `1`–`65535` | 리슨할 로컬 포트 |
| `basePath` | URL 경로 접두사 | 어떤 베이스 경로 아래 제공 |
| `latencyMs` | `0`–`10000` | 네트워크 지연을 모방하는 인위적 지연 |
| `overrides` | 최대 100개 응답 재정의 | 선택한 작업에 특정 응답 반환 |

잘못된 포트나 지연 값은 고장난 서버를 시작하지 않고 명확한 메시지로 거부됩니다.

## 여러 모크

여러 모크를 동시에 실행할 수 있습니다——예를 들어 연 문서마다 하나. 앱이 실행 중 모크를 나열하고(`mock:list`) 개별로 멈출 수 있습니다(`mock:stop`). 각 모크는 문서 ID와 이름에 연결돼 구분됩니다.

## 받은 요청 확인

모크는 받은 요청을 기록합니다. 조회할 수 있고(`mock:requests`, 선택적 제한) 기록을 지울 수 있습니다. 실제 백엔드가 없어도 클라이언트가 예상 매개변수로 올바른 작업을 호출하는지 확인하는 데 도움됩니다.

## 응답 재정의

기본 샘플이나 스키마 유도 응답이 부족할 때 응답 재정의로 특정 작업에 선택한 응답을 반환합니다. 구성을 예측 가능하게 유지하도록 재정의에 상한(최대 100)이 있습니다.

## 사용 시점

- 아직 구축 중인 계약에 대해 프런트엔드 개발 블록 해제.
- 지연과 응답을 조정해 느린 상황이나 엣지 케이스 재현.
- 배포 환경 없이 API 플로우 시연.
- 생성 클라이언트가 설계대로 작업을 호출하는지 검증.

모크는 다른 모든 모드와 같은 스펙을 읽어 설계 변경 시 항상 계약과 정렬됩니다.
