# Powerduck Cloud

Powerduck Cloud 让一份 OpenAPI 文件变成你可以**分享**的东西。添加一份规范，选择暴露什么，把渲染文档和托管 MCP 服务器的稳定链接交给别人——无需自己托管或运行任何程序。

它与桌面客户端是同样的契约优先、AI 辅助工作流，只是为团队和消费者搬到了线上。

## 旅程

1. **添加一份规范**，可以上传文件、指向 Git 仓库或粘贴 URL。你甚至可以在官网开始流程，准备好时再登录——不必上传两次。
2. **选择暴露什么。** 单独开启或关闭各个操作；你的原始文件从不会被修改。
3. **立即打开文档链接**——渲染的 API 文档默认开启。托管 MCP 端点只差一个开关，在你选择向智能体暴露工具之前保持关闭。
4. **控制访问。** 添加文档查看密码和有效期，以及给智能体的独立 MCP 访问密钥。
5. **发布并分享。** 为当前版本发布一个就绪产物，让链接可解析；高级控件一键可达。
6. **保持最新。** 每次更改创建一个新版本，可对比或回滚，Git 来源可在更新时同步。
7. **管理生命周期。** 暂停、恢复或归档文档；一眼查看其状态、版本和来源。

## 你会得到什么

- **稳定的文档链接**，在你发布新版本时仍保持可读；
- **托管 MCP 端点**，让他人的 AI 智能体能够发现并调用你选择的操作；
- **按操作暴露**，让内部或未完成的接口不进入公开面；
- **访问控制**，含查看密码、有效期和 MCP 访问密钥；
- **版本历史**，含对比和回滚——原始内容从不会被覆盖；
- **Git 同步**，让仓库更新流入新的托管版本；
- **自定义域名**，包括子路径配置，带来品牌化体验。

### 一份文档，多个版本

每次编辑创建新版本而非覆盖原始内容，因此你可以对比版本、回滚，并针对已知状态重新发布文档和 MCP。文档和 MCP 始终绑定到特定文档和版本，从不会指向模糊的"最新"。

### 为什么链接可能打不开

当三件事齐备时，文档或 MCP 链接才可解析，文档工作区会展示每一项，并高亮第一个未满足的要求：

1. 文档处于**活动**状态——暂停它会让文档和 MCP 一起下线；
2. 你分享的形态已**启用**——文档和 MCP 各有自己的开关（文档默认开启，MCP 默认关闭）；
3. 当前产物已**发布**——在你添加版本或更改暴露操作后它会自动构建，因此通常你无需操作；手动发布作为兜底可用。

访问检查——查看密码、有效期或 MCP 访问密钥——在这三者之上生效。

## 登录与归属

用 **Google** 或 **GitHub** 登录。OAuth 握手之后，Powerduck 以安全、HttpOnly 的 Cookie 签发自己的会话——服务商的令牌从不会用作你的长期身份。一切都归属于一个**组织**；个人组织会自动创建，团队以后可以共享一个而无需重新设计。

## 控制台

- **Dashboard（仪表盘）**——添加规范，查看最近文档及快速链接和起停动作；
- **Projects（项目）**——组织文档；
- **文档工作区**——状态、文档、MCP、暴露操作、版本、来源和域名，分清晰、带标签的区块；
- **Billing（账单）**——订阅状态和订单，保持分开；
- **Hub**——发布并浏览公开文档和 MCP 服务器；
- **Settings（设置）**和 **Activity（活动）**——个人资料、偏好和审计日志。

公开读者使用专门的文档查看器，除非文档要求密码，否则无需账号。

## Cloud 与桌面客户端

| | 桌面客户端 | Cloud |
|---|---|---|
| 运行 | 在你机器上 | 托管 |
| 模式 | 一次性永久授权 | 按月订阅 |
| 产出 | 授权码（仅展示一次） | 会员资格，无授权码 |
| 最适合 | 本地、离线、完整工作区 | 在线分享和发布 |

两者互补、分开出售。参见[账单](./billing)。
