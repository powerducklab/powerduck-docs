# ローカルモックサーバー

モックサーバーは仕様から直接 API の動くスタンドを提供するため、バックエンドの準備前にフロントエンドやクライアント作業を進められます。外部インフラを立てる必要もありません。デスクトップのメインプロセスで動きます。

## モックを起動する

モックサーバーモードから、または AI チャットから直接起動できます。チャットから起動すると、アプリはサービス提供中のアドレスを確認します。

以下のオプションがあります。

| オプション | 範囲/形 | 用途 |
|---|---|---|
| `port` | 整数 `1`–`65535` | リッスンするローカルポート |
| `basePath` | URL パスプレフィックス | あるベースパス配下で提供 |
| `latencyMs` | `0`–`10000` | ネットワーク遅延を模倣する人為遅延 |
| `overrides` | 最大 100 件のレスポンスオーバーライド | 選んだ操作に特定レスポンスを返す |

無効なポートやレイテンシ値は、壊れたサーバーを起動するのではなく、明確なメッセージで拒否されます。

## 複数のモック

複数のモックを同時に実行できます——例えば開いた文書ごとに 1 つ。アプリは実行中のモックを列挙し（`mock:list`）、個別に停止できます（`mock:stop`）。各モックは文書 ID と名前に紐づき、区別できます。

## 受け取ったリクエストを確認する

モックは受け取ったリクエストを記録します。クエリでき（`mock:requests`、任意で件数制限）、記録をクリアできます。実バックエンドがなくても、クライアントが期待するパラメータで正しい操作を呼んでいるか確認するのに役立ちます。

## レスポンスオーバーライド

デフォルトのサンプルやスキーマ導出のレスポンスで足りないとき、レスポンスオーバーライドで特定操作に選んだレスポンスを返せます。設定を予測可能に保つため、オーバーライドには上限（最大 100 件）があります。

## 使う場面

- まだ構築中の契約に対し、フロントエンド開発のブロックを解除する。
- レイテンシとレスポンスを調整し、遅延やエッジケースを再現する。
- デプロイ環境なしで API フローをデモする。
- 生成クライアントが設計どおりに操作を呼ぶか検証する。

モックは他のすべてのモードと同じ仕様を読むため、設計が変わると常に契約と整合します。
