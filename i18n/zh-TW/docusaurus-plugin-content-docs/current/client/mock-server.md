# 本機 Mock 伺服器

Mock 伺服器直接根據規範為你的 API 提供一個可用的替身，因此前端和用戶端工作可以在後端就緒前推進——也無需搭建外部基礎設施。它執行在桌面主程序中。

## 啟動 Mock

你可以從 Mock 伺服器形態或直接從 AI 對話啟動 Mock。從對話啟動時，應用程式會確認它提供服務的位址。

以下選項可用：

| 選項 | 範圍/形態 | 用途 |
|---|---|---|
| `port` | 整數 `1`–`65535` | 監聽的本機連接埠 |
| `basePath` | URL 路徑前綴 | 在某個基礎路徑下提供 Mock |
| `latencyMs` | `0`–`10000` | 新增人為延遲以模擬網路時延 |
| `overrides` | 最多 100 條回應覆蓋 | 為選定操作回傳特定回應 |

無效的連接埠或延遲值會以清晰資訊被拒絕，而不是啟動一個壞掉的伺服器。

## 多個 Mock

你可以同時執行多個 Mock——例如每個打開的文件一個。應用程式會列出執行中的 Mock（`mock:list`），並可停止單個 Mock（`mock:stop`）。每個 Mock 都關聯一個文件 ID 和名稱，讓它們保持可區分。

## 檢查收到的請求

Mock 會記錄它收到的請求。你可以查詢它們（`mock:requests`，可選數量限制），並清空記錄。即使沒有真實後端，這也有助於確認用戶端是否以預期參數呼叫了正確的操作。

## 回應覆蓋

當預設範例或由模式推導的回應不夠時，回應覆蓋可讓某個特定操作回傳選定的回應。覆蓋有上限（最多 100 條），以保持配置可預測。

## 何時使用

- 針對仍在建構的合約，解除前端開發的阻塞；
- 透過調整延遲和回應，重現慢速或邊緣情形；
- 在沒有已部署環境的情況下示範 API 流程；
- 驗證產生的用戶端是否按設計呼叫操作。

Mock 與其他每個形態讀取同一份規範，因此當設計變化時它始終與合約對齊。
