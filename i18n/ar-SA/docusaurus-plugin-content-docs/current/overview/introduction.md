# مقدمة

تتغيّر طريقة بناء واجهات برمجة التطبيقات. طوال عشرين عاماً، كان **المشغّل** إنساناً ينقر في واجهة، وكان **مستهلك** عقد الواجهة إنساناً يقرأ التوثيق. اليوم يتغيّر الطرفان.

- يصبح المشغّل **مساعداً ذكياً** يحوّل النية إلى إجراءات.
- يصبح المستهلك **وكيل ذكاء اصطناعي** يستدعي الواجهة كأداة عبر MCP.

أدوات الحقبة السابقة — عملاء الواجهة، عارضو المواصفات، مجموعات الطلبات — صُمّمت لإنسان خلف لوحة المفاتيح. أما Powerduck فمصمّم لهذا العصر. ليس عميل واجهة أفضل ولا عارض مواصفات أجمل. إنه **منصة أصلية للذكاء الاصطناعي تنطلق من ملف OpenAPI واحد**.

## النواة: ملف OpenAPI محلي واحد

يبدأ كل شيء بملف `openapi.yaml` بسيط في مستودعك: ملف مفتوح ومُنسَّخ ويمكن للبشر والذكاء الاصطناعي قراءته. بلا قاعدة بيانات احتكارية وبلا حساب سحابي.

```text
                one local openapi.yaml
                         |
      you + AI -> design debug test mock docs data-model
                         |
                      MCP tools
                         |
               any AI coding agent
```

هذا الملف الواحد هو العقد. كل تدفّق يقرأ منه، ويمكن تمرير الملف نفسه عبر MCP إلى أي وكيل برمجة ذكي. هكذا تشترك أنت والمساعد المدمج وأي وكيل خارجي في مصدر حقيقة واحد. عندما يقرأ التصميم والتصحيح والاختبار والمحاكاة والتوثيق الملف نفسه، تتوقّف «مزامنة الأدوات» عن كونها مهمة: ليست هدفاً، بل نتيجة طبيعية للتصميم.

يدعم Powerduck OpenAPI 3.2 ويرقّي فوراً مستندات 3.0 / 3.1 القائمة (وSwagger 2.0). تُنمذَج الواجهات غير HTTP — SSE وWebSocket وGraphQL وgRPC وMCP — كمدخلات مسار عادية عبر امتداد `x-protocol`، دون تحويل قسري إلى أشكال REST.

## العمل مع الذكاء الاصطناعي

- فور فتح ملف YAML، يقترح المساعد ما يمكن فعله به.
- صف النتيجة بلغة طبيعية — «أنشئ نقطة نهاية الطلبات»، «جهّز بيانات اختبار»، «شغّل تدفّق الدفع وأنشئ تقريراً» — فيختار الأدوات المناسبة ويقترح التغييرات.
- يأتي كل تغيير كـ**بطاقة قابلة للمراجعة**. لا يُطبَّق شيء قبل موافقتك.
- عند صقل واجهة ما، يبقى المساعد على تلك الواجهة ولا يغيّر إلا المطلوب، دون المساس ببقية المستند.
- يمكنك إحضار **أي نموذج متوافق مع OpenAI**. على سطح المكتب، لا تغادر التعليمات والمفاتيح جهازك أبداً.

## محلي أولاً افتراضياً

يعمل Powerduck على جهازك، ويفتح ويحفظ ملفات حقيقية، ويعمل دون اتصال، ويُبقي مفاتيح الواجهة والتعليمات خارج المتصفح. السحابة امتداد اختياري للمشاركة والنشر، لا شرط للبدء.

## ثلاث طرق لاستخدام Powerduck

| الطريقة | ما هي | متى تُستخدم |
|---|---|---|
| [**عميل سطح المكتب**](../client/introduction) | تطبيق Electron محلي أولاً مع مساعد ذكي ومساحة عمل كاملة | مهندسون يريدون كل شيء على أجهزتهم، والعمل دون اتصال، وإبقاء المفاتيح/التعليمات محلية |
| [**Powerduck Cloud**](../cloud/introduction) | خدمة مستضافة لاستضافة OAS والتوثيق عبر الإنترنت وMCP المُدار | لمشاركة الواجهات ونشر روابط ثابتة وتقديم MCP دون تشغيل أي شيء |
| [**مكتبات مفتوحة المصدر**](../opensource/) | حزم npm باسم `@powerduck/*` قابلة للتركيب | لبناء أدواتك أو خطوط CI أو مكونات مدمجة |

تشترك الطرق الثلاث في المحرك نفسه. يُجمَّع عميل سطح المكتب والسحابة كلاهما من المكتبات مفتوحة المصدر، لذا تتصرف القدرات بالطريقة نفسها سواء نُفّذت محلياً أو استُدعيت عبر الشبكة أو استُوردت الحزم مباشرة.

### عميل سطح المكتب

يعمل [عميل سطح المكتب](../client/introduction) بالكامل على جهازك. يفتح ويعدّل ملفات حقيقية على القرص، ويرسل الطلبات عبر عملية محلية، ويشغّل محاكيات محلية، ويُبقي تعليمات الذكاء الاصطناعي ومفاتيح الواجهة خارج وحدة تحكم المتصفح. النماذج قابلة للتهيئة بحرية، وتأتي التغييرات المقترحة كبطاقات قابلة للمراجعة قبل التطبيق.

### Powerduck Cloud

تنقل [Powerduck Cloud](../cloud/introduction) التدفّق نفسه إلى الإنترنت. أضف ملفاً أو مستودع Git أو رابطاً، واختر العمليات المراد عرضها، فتحصل على روابط ثابتة للتوثيق المعروض ونقطة نهاية MCP مُدارة. يمكن حماية الوصول بكلمة مرور عرض أو مفتاح وصول MCP؛ وتضيف الخطط المدفوعة مزامنة Git ونطاقات مخصصة وحدوداً أعلى.

### مكتبات مفتوحة المصدر

[المكتبات](../opensource/) هي المحرك الأساسي: محلّل ومُرقٍّ لـ OpenAPI، وCLI متعدد البروتوكولات، ومولّد كود، وخادم MCP، ومنفّذ طلبات، ومحوّلات cURL / Postman، ومحررات مدمجة. يُنشَر كل واحد بشكل مستقل على npm مع أدلة تثبيت مخصصة ومراجع API. التفاصيل التقنية منخفضة المستوى موجودة هنا.

## ما الذي يتغيّر لك

- **صف النتيجة لا النقرات.** قُل الهدف ويتقدّم المساعد بخطوات قابلة للمراجعة.
- **واجهاتك جاهزة للوكلاء منذ البداية.** العقد نفسه الذي يولّد التوثيق يولّد أدوات MCP، كي تستدعي وكلاء الذكاء الاصطناعي واجهتك بشكل صحيح منذ اليوم الأول.
- **بلا انحراف.** التصميم والتصحيح والاختبار والمحاكاة والتوثيق تقرأ ملفاً واحداً.
- **كل البروتوكولات في مكان واحد.** HTTP وSSE وWebSocket وGraphQL وgRPC وMCP في مواصفة واحدة، لا ست أدوات.
- **بلا قفل.** أحضر نماذجك، وأبقِ المفاتيح محلية على سطح المكتب، وامتلك ملف YAML نصياً في مستودعك.
