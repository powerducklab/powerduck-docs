# AI 与模型

Powerduck 允许你选择并配置助手使用的模型。桌面端通过主进程向指定端点发送请求；文档修改仍通过可审阅的卡片进行。

## 自带模型

在设置中针对任何**兼容 OpenAI** 的 Chat Completions 端点配置助手：

- 选择内置的服务商预设，或定义一个**自定义**服务商；
- 提供显示名称、基础 URL、API 密钥和模型 ID；
- 可以配置并选择多个配置文件。

模型不限定于某个服务商。自托管或第三方 OpenAI 兼容端点采用相同的接入方式，便于团队遵循自己的模型使用政策。

## 高级能力与优雅回退

每个配置文件都有一个**高级能力**选项，默认开启：

- 开启时，应用使用模型的**原生函数调用**，通过网络发送工具目录，让模型可以直接选择并调用合适的工具；
- 如果某个端点拒绝原生工具参数——例如不支持工具的较小模型——该端点会被记住，请求会通过**基于内容的回退协议**重试一次。

回退机制有助于提高兼容性，但不保证请求一定成功：网络、认证和模型错误仍可能发生。如果某个配置需要始终使用基础方式，可以关闭高级能力。

工具执行也有边界：智能体的工具轮次有限，默认为三轮，并会在同一次运行中对重复调用去重。

## 为什么请求要经过主进程

在桌面客户端，补全请求从 **Node 主进程**发出，而不是网页视图。这有两个具体好处：

- **没有浏览器 CORS 墙。** 适用于网页的跨域限制不会阻挡对模型端点的调用；
- **HTTP 请求在渲染进程之外执行。** 渲染进程的网络面板不显示主进程的 HTTP 通信，但这不保证提示词或密钥不会出现在渲染进程内存、日志或其他开发者工具中。

桌面网关会验证请求结构并限制资源使用：

- 只接受 HTTP(S) URL，并检查请求头名称和值、正文大小、超时和并发请求数。允许本地和私有端点。这不是主机白名单，也不是对上游服务商隐私行为的保证；
- 请求可以取消（`ai:cancel`）。

## 桌面与 Web

同一个助手在两种运行时中都能工作，使用各自适配的通道：

- **桌面（Electron）：** 能力在本地引入并执行，补全请求通过主进程代理；
- **Web：** 同样的工作流通过 HTTP 运行，调用服务 API 而非本地模块。

这正是应用在 Electron 路径之外保留 Web 兼容路径的原因：意图处理和卡片表现一致，只是传输方式随运行时改变。

## 意图如何被识别

意图不是通过为每个功能枚举关键词来处理的。应用改为向模型呈现一个明确、描述清晰的**工具目录**——每个工具的 ID、参数以及应在何种确切情形下使用。模型从目录中选择最佳工具，确定性宿主校验并执行它，写入动作要求确认。

因此增加一个能力意味着向目录添加一个工具（并准确描述它），而不是维护更长的关键词列表。同一个目录还可以通过 MCP 服务器与外部智能体共享，让能力在产品和其他工具之间保持对齐。

## 隐私姿态

- 提示词、选定的上下文、工具说明和凭据会发送到你配置的模型端点。托管服务商会接收这些数据；若政策要求本地推理，请使用可信的本地端点；
- 是确定性宿主——而非模型——校验并应用每项改动；
- 每次写入在运行前都由你批准。
