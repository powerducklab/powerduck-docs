# AI とモデル

Powerduck ではアシスタントのモデルを選択・設定できます。デスクトップ版はメインプロセスから指定したエンドポイントへリクエストを送り、ドキュメントの変更は引き続き確認可能なカードで行います。

## モデルを持ち込む

設定で、任意の **OpenAI 互換**の Chat Completions エンドポイントにアシスタントを構成します。

- 組み込みのプロバイダープリセットを選ぶか、**カスタム**プロバイダーを定義する。
- 表示名、ベース URL、API キー、モデル ID を提供する。
- 複数のプロファイルを構成して選べる。

特定のプロバイダーには依存しません。セルフホスト型やサードパーティーの OpenAI 互換エンドポイントも同じ方法で利用でき、チーム独自のモデル利用方針に対応できます。

## 高度な能力と優雅なフォールバック

各プロファイルには**高度な能力**オプションがあり、デフォルトで有効です。

- 有効なとき、アプリはモデルの**ネイティブ関数呼び出し**を使い、ツールカタログをネットワーク越しに送り、モデルが適切なツールを直接選んで呼べるようにします。
- あるエンドポイントがネイティブのツール引数を拒否した場合——ツール非対応の小さなモデルなど——そのエンドポイントは記憶され、**コンテンツベースのフォールバックプロトコル**で一度リトライします。

フォールバックは互換性を高めますが、成功を保証しません。ネットワーク、認証、モデルのエラーは引き続き発生し得ます。常に基本方式を使うプロファイルでは高度な機能を無効にしてください。

ツール実行にも上限があります。エージェントのツール処理はデフォルトで 3 ラウンドまでで、同一実行内の重複呼び出しを除きます。

## なぜリクエストをメインプロセス経由にするか

デスクトップクライアントでは、補完リクエストは WebView ではなく **Node メインプロセス**から発行されます。これには 2 つの具体的な利点があります。

- **ブラウザの CORS の壁がない。** Web に適用されるクロスオリジン制限がモデルエンドポイントへの呼び出しを妨げません。
- **HTTP リクエストはレンダラーの外部で実行されます。** レンダラーのネットワークパネルにはメインプロセスの HTTP 通信は表示されません。ただし、プロンプトやキーがレンダラーのメモリー、ログ、その他の開発者ツールに存在しないことを保証するものではありません。

デスクトップのゲートウェイはリクエスト構造を検証し、リソース制限を適用します。

- HTTP(S) URL のみ受け付け、ヘッダー名と値、ボディーサイズ、タイムアウト、同時リクエスト数を確認します。ローカルおよびプライベートのエンドポイントも利用できます。これはホストの許可リストでも、接続先のプライバシー保証でもありません。
- リクエストはキャンセルできます（`ai:cancel`）。

## デスクトップと Web

同じアシスタントが両方の実行環境で動き、それぞれに適した経路を使います。

- **デスクトップ（Electron）:** 能力はローカルに import されて実行され、補完リクエストはメインプロセス経由でプロキシされます。
- **Web:** 同じワークフローが HTTP 越しに実行され、ローカルモジュールではなくサービス API を呼びます。

これこそ、アプリが Electron 経路に加えて Web 互換経路を保つ理由です。意図処理とカード表現は一致し、トランスポートだけが実行環境に応じて変わります。

## 意図はどう識別されるか

意図は機能ごとにキーワードを列挙して処理されません。代わりにアプリは、明確でよく説明された**ツールカタログ**をモデルに提示します——各ツールの ID、引数、どんな正確な状況で使うか。モデルはカタログから最適なツールを選び、確定的ホストがそれを検証して実行し、書き込み操作は確認を求めます。

そのため能力を足すことは、より長いキーワードリストの保守ではなく、カタログへのツール追加（と正確な記述）を意味します。同じカタログは MCP サーバー越しに外部エージェントとも共有でき、製品と他のツール間で能力が整合します。

## プライバシー姿勢

- プロンプト、選択したコンテキスト、ツールの説明、認証情報は設定したモデルのエンドポイントへ送信されます。ホスト型のプロバイダーはそのデータを受信します。ローカル推論が必要な方針の場合は、信頼できるローカルのエンドポイントを使用してください。
- 各変更を検証し適用するのはモデルではなく確定的ホストです。
- すべての書き込みは実行前にあなたの承認を得ます。
