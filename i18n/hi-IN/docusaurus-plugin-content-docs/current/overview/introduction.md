# परिचय

API बनाने का तरीका बदल रहा है। पिछले दो दशकों में **ऑपरेटर** वह व्यक्ति होता था जो ग्राफ़िकल इंटरफ़ेस पर क्लिक करता था, और API कॉन्ट्रैक्ट का **उपयोगकर्ता** वह व्यक्ति होता था जो दस्तावेज़ पढ़ता था। अब दोनों भूमिकाएँ बदल रही हैं:

- ऑपरेटर की भूमिका बढ़ती हुई संख्या में **AI असिस्टेंट** निभा रहे हैं, जो आपके इरादे को कार्रवाई में बदलते हैं;
- कॉन्ट्रैक्ट का उपयोग बढ़ती हुई संख्या में **AI एजेंट** कर रहे हैं, जो MCP के ज़रिए API को टूल की तरह कॉल करते हैं।

पिछले दौर के टूल—API क्लाइंट, स्पेसिफ़िकेशन व्यूअर और रिक्वेस्ट कलेक्शन—कीबोर्ड पर काम करने वाले व्यक्ति के लिए बनाए गए थे। Powerduck इस नए दौर के लिए बनाया गया है। यह केवल बेहतर API क्लाइंट या अधिक सुंदर स्पेसिफ़िकेशन व्यूअर नहीं, बल्कि **एक OpenAPI फ़ाइल से शुरू होने वाला AI-सक्षम प्लेटफ़ॉर्म** है।

## आधार: एक लोकल OpenAPI फ़ाइल

सब कुछ आपकी रिपॉज़िटरी में मौजूद एक सामान्य `openapi.yaml` फ़ाइल से शुरू होता है। इसका फ़ॉर्मैट खुला है, इसे वर्ज़न कंट्रोल में रखा जा सकता है और इंसान व AI दोनों इसे पढ़ सकते हैं। शुरुआत किसी बंद डेटाबेस या क्लाउड खाते से नहीं होती।

```text
                one local openapi.yaml
                         |
      you + AI -> design debug test mock docs data-model
                         |
                      MCP tools
                         |
               any AI coding agent
```

यही फ़ाइल कॉन्ट्रैक्ट है। हर वर्कफ़्लो इसे पढ़ता है और यही फ़ाइल MCP के ज़रिए किसी भी AI कोडिंग एजेंट को दी जा सकती है। इस तरह आप, बिल्ट-इन असिस्टेंट और सभी बाहरी एजेंट एक ही प्रामाणिक स्रोत का इस्तेमाल करते हैं। जब डिज़ाइन, डीबगिंग, टेस्ट, मॉक और दस्तावेज़ एक ही फ़ाइल पढ़ते हैं, तो टूल को सिंक में रखना अलग काम नहीं रह जाता। यह इस डिज़ाइन का परिणाम है।

Powerduck OpenAPI 3.2 के साथ काम करता है। यह मौजूदा 3.0 और 3.1 दस्तावेज़ों तथा Swagger 2.0 को उसी जगह अपग्रेड करके पढ़ता है। गैर-HTTP API—SSE, WebSocket, GraphQL, gRPC और MCP—को केवल REST वाली संरचना में ढालने के बजाय `x-protocol` एक्सटेंशन से सामान्य पाथ आइटम के रूप में मॉडल किया जाता है।

## AI के साथ काम करना

- YAML फ़ाइल खोलते ही असिस्टेंट सुझाव देता है कि आप उससे क्या कर सकते हैं;
- सामान्य भाषा में अपना लक्ष्य बताएँ, जैसे “ऑर्डर के एंडपॉइंट बनाएँ”, “टेस्ट डेटा तैयार करें” या “चेकआउट फ़्लो चलाकर रिपोर्ट दें”। असिस्टेंट सही टूल चुनकर बदलाव सुझाता है;
- हर बदलाव एक **समीक्षा योग्य कार्ड** के रूप में आता है। आपकी मंज़ूरी से पहले कुछ भी लागू नहीं होता;
- जब आप किसी एक API को सुधार रहे हों, तो असिस्टेंट उसी API पर केंद्रित रहता है और केवल माँगे गए बदलाव करता है, दस्तावेज़ के अन्य हिस्सों में नहीं भटकता;
- लोकल फ़ाइलें डिस्क पर ही रहती हैं। रिमोट AI ज़रूरी संदर्भ आपके कॉन्फ़िगर किए हुए मॉडल सेवा प्रदाता को उसके क्रेडेंशियल के साथ भेजता है। Cloud पर प्रकाशित करने से चुना हुआ कंटेंट अपलोड होता है। वैकल्पिक उपयोग आँकड़े डिफ़ॉल्ट रूप से बंद रहते हैं और अलग से नियंत्रित होते हैं। लोकल काम के लिए खाते की ज़रूरत नहीं है।

## डिफ़ॉल्ट रूप से लोकल काम को प्राथमिकता

Powerduck आपके कंप्यूटर पर चलता है, वास्तविक फ़ाइलें खोलता और सेव करता है, ऑफ़लाइन काम करता है तथा API की और प्रॉम्प्ट को ब्राउज़र से बाहर रखता है। क्लाउड शेयर करने और प्रकाशित करने का वैकल्पिक साधन है, शुरुआत करने की शर्त नहीं।

## Powerduck इस्तेमाल करने के तीन तरीके

| उत्पाद | यह क्या है | किसके लिए उपयोगी है |
|---|---|---|
| [**डेस्कटॉप क्लाइंट**](/docs/hi-IN/client/introduction/) | लोकल काम को प्राथमिकता देने वाला Electron ऐप, जिसमें AI असिस्टेंट और पूरा API वर्कस्पेस है | वे डेवलपर जो अपने कंप्यूटर पर काम करना, ऑफ़लाइन रहना और की व प्रॉम्प्ट को लोकल रखना चाहते हैं |
| [**Powerduck Cloud**](/docs/hi-IN/cloud/introduction/) | OAS होस्टिंग, ऑनलाइन दस्तावेज़ और मैनेज्ड MCP की सेवा | API शेयर करना, स्थायी लिंक प्रकाशित करना और अपना सर्वर चलाए बिना MCP उपलब्ध कराना |
| [**ओपन-सोर्स लाइब्रेरी**](/docs/hi-IN/opensource/) | साथ इस्तेमाल किए जा सकने वाले `@powerduck/*` npm पैकेज | अपने टूल, CI पाइपलाइन या एम्बेड किए जाने वाले कंपोनेंट बनाना |

तीनों उत्पाद एक ही इंजन का इस्तेमाल करते हैं। डेस्कटॉप क्लाइंट और क्लाउड दोनों ओपन-सोर्स लाइब्रेरी से बने हैं। इसलिए कोई सुविधा लोकल चलाने, नेटवर्क से कॉल करने या सीधे पैकेज इंपोर्ट करने पर एक जैसा व्यवहार करती है।

### डेस्कटॉप क्लाइंट

[डेस्कटॉप क्लाइंट](/docs/hi-IN/client/introduction/) पूरी तरह आपके कंप्यूटर पर चलता है। यह डिस्क की वास्तविक फ़ाइलें खोलता और संपादित करता है, लोकल प्रक्रिया से रिक्वेस्ट भेजता है, लोकल मॉक चलाता है तथा AI प्रॉम्प्ट और API की को ब्राउज़र कंसोल से बाहर रखता है। मॉडल को आप अपनी ज़रूरत के अनुसार कॉन्फ़िगर कर सकते हैं। लागू होने से पहले हर प्रस्तावित बदलाव समीक्षा के लिए कार्ड में दिखाई देता है।

### Powerduck Cloud

[Powerduck Cloud](/docs/hi-IN/cloud/introduction/) उसी वर्कफ़्लो को ऑनलाइन उपलब्ध कराता है। फ़ाइल, Git रिपॉज़िटरी या URL जोड़ें; उपलब्ध कराने वाले ऑपरेशन चुनें; और रेंडर किए गए दस्तावेज़ व मैनेज्ड MCP एंडपॉइंट के स्थायी लिंक पाएँ। देखने के लिए पासवर्ड या MCP एक्सेस की लगाकर पहुँच सुरक्षित की जा सकती है। सशुल्क प्लान में Git सिंक, कस्टम डोमेन और अधिक उपयोग सीमाएँ मिलती हैं।

### ओपन-सोर्स लाइब्रेरी

[लाइब्रेरी](/docs/hi-IN/opensource/) उत्पाद के पीछे काम करने वाले इंजन हैं: OpenAPI पार्सर और अपग्रेडर, कई प्रोटोकॉल वाला CLI, कोड जनरेटर, MCP सर्वर, रिक्वेस्ट रनर, cURL और Postman कन्वर्टर तथा एम्बेड किए जा सकने वाले एडिटर। हर लाइब्रेरी npm पर अलग प्रकाशित होती है और उसका अपना इंस्टॉलेशन गाइड व API संदर्भ होता है। विस्तृत तकनीकी जानकारी इन्हीं में मिलती है।

## आपके काम में क्या बदलता है

- **आप परिणाम तय करते हैं, क्लिक का क्रम नहीं।** लक्ष्य बताएँ, और असिस्टेंट समीक्षा योग्य चरणों में काम पूरा करता है।
- **आपकी API एजेंट के लिए तैयार होती हैं।** जो कॉन्ट्रैक्ट दस्तावेज़ बनाता है, वही MCP टूल भी बनाता है, ताकि AI एजेंट शुरुआत से ही API को सही तरीके से कॉल कर सकें।
- **सब कुछ एक-दूसरे के अनुरूप रहता है।** डिज़ाइन, डीबगिंग, टेस्ट, मॉक और दस्तावेज़ एक ही फ़ाइल पढ़ते हैं।
- **सभी प्रोटोकॉल एक जगह मिलते हैं।** HTTP, SSE, WebSocket, GraphQL, gRPC और MCP छह अलग टूल के बजाय एक ही स्पेसिफ़िकेशन में रहते हैं।
- **किसी एक प्रदाता पर निर्भरता नहीं होती।** अपना मॉडल चुनें, डेस्कटॉप पर की लोकल रखें और रिपॉज़िटरी की YAML फ़ाइल पर अपना नियंत्रण बनाए रखें।

- पूरा लोकल वर्कस्पेस चाहिए? [डेस्कटॉप क्लाइंट गाइड](/docs/hi-IN/client/introduction/) पढ़ें।
- API ऑनलाइन प्रकाशित करनी है? [Cloud गाइड](/docs/hi-IN/cloud/introduction/) पढ़ें।
- अपनी इंटीग्रेशन बना रहे हैं? [ओपन-सोर्स लाइब्रेरी](/docs/hi-IN/opensource/) देखें।
