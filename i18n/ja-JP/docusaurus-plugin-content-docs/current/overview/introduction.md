# はじめに

API の構築方法は変化しつつあります。この 20 年、**操作者**は GUI をクリックする人であり、API 契約の**利用者**はドキュメントを読む人でした。今、その両端が変わっています。

- 操作者は、意図を行動に変える **AI アシスタント**になりつつあります。
- 利用者は、MCP を通じて API をツールとして呼び出す **AI エージェント**になりつつあります。

前の時代を形作ったツール——API クライアント、仕様ビューア、リクエストコレクション——はキーボードの前にいる人間のために作られていました。Powerduck はこの時代のために作られています。それはより優れた API クライアントでも、より美しい仕様ビューアでもありません。**1 つの OpenAPI ファイルから始まる AI ネイティブのプラットフォーム**です。

## 中核となるもの: 1 つのローカル OpenAPI ファイル

すべてはリポジトリ内のありふれた `openapi.yaml` から始まります。オープンで、バージョン管理され、人間にも AI にも読めるファイルです。専有データベースでも、クラウドアカウントでもありません。

```text
                one local openapi.yaml
                         |
      you + AI -> design debug test mock docs data-model
                         |
                      MCP tools
                         |
               any AI coding agent
```

その 1 つのファイルが契約です。すべてのワークフローがそこから読み取り、同じファイルを MCP 経由で任意の AI コーディングエージェントに渡せます。そのため、あなたと内蔵アシスタント、すべての外部エージェントが単一の信頼できる情報源を共有します。設計、デバッグ、テスト、モック、ドキュメントがすべて同じファイルを読むとき、「ツール間の同期を保つ」ことは単にタスクでなくなります。これは目標ではなく、設計がもたらす結果です。

Powerduck は OpenAPI 3.2 に対応し、既存の 3.0 / 3.1 文書（および Swagger 2.0）をその場でアップグレードして読み取ります。HTTP 以外の API——SSE、WebSocket、GraphQL、gRPC、MCP——は、REST 専用の形に無理に押し込めるのではなく、`x-protocol` 拡張を通じて通常のパス項目としてモデル化されます。

## AI との働き方

- YAML を開くと、アシスタントがすぐにそれでできることを提案します。
- 「注文エンドポイントを作って」「テストデータを準備して」「チェックアウトフローを実行してレポートを出して」と、平易な言葉で結果を伝えると、アシスタントが適切なツールを選び、変更を提案します。
- すべての変更は**レビュー可能なカード**として届きます。あなたが承認するまで何も適用されません。
- ある API を refine するとき、アシスタントはその API に留まり、依頼された箇所だけを変更し、文書全体にブレていきません。
- **OpenAI 互換の任意のモデル**を持ち込めます。デスクトップでは、プロンプトとキーはマシンの外に出ません。

## デフォルトはローカルファースト

Powerduck はあなたのマシン上で動き、実際のファイルを開いて保存し、オフラインで動作し、API キーとプロンプトをブラウザから遠ざけます。クラウドは共有と公開のための任意の拡張であり、始めるための前提ではありません。

## Powerduck を使う 3 つの方法

| 形態 | それは何か | 適している場面 |
|---|---|---|
| [**デスクトップクライアント**](../client/introduction.md) | AI アシスタントと完全な API ワークスペースを備えたローカルファーストの Electron アプリ | すべてを自分のマシンに置き、オフラインで働き、キーとプロンプトをローカルに保ちたいエンジニア |
| [**Powerduck Cloud**](../cloud/introduction.md) | OAS ホスティング、オンラインドキュメント、マネージド MCP のためのホスト型サービス | API を他者と共有し、安定したリンクを公開し、何も実行せずに MCP を提供したい場合 |
| [**オープンソースライブラリ**](/opensource/index.md) | 組み合わせ可能な `@powerduck/*` npm パッケージ | 独自のツール、CI パイプライン、埋め込みコンポーネントを構築する場合 |

3 つの形態は同じエンジンを共有します。デスクトップクライアントとクラウドはどちらもオープンソースライブラリから組み立てられているため、ローカルで実行しても、ネットワーク経由で呼び出しても、パッケージを直接 import しても、機能は同じように動作します。

### デスクトップクライアント

[デスクトップクライアント](../client/introduction.md)は完全にあなたのマシン上で動作します。ディスク上の実際のファイルを開いて編集し、ローカルプロセス経由でリクエストを送り、ローカルモックを実行し、AI プロンプトと API キーをブラウザのコンソールから遠ざけます。モデルは自由に設定でき、提案される変更は適用前にレビュー可能なカードで届きます。

### Powerduck Cloud

[Powerduck Cloud](../cloud/introduction.md) は同じワークフローをオンラインに持ち出します。ファイル、Git リポジトリ、URL を追加し、公開する操作を選ぶと、レンダリングされたドキュメントの安定リンクとマネージド MCP エンドポイントが得られます。アクセスは閲覧パスワードや MCP アクセスキーで保護でき、有料プランでは Git 同期、カスタムドメイン、より高い上限が追加されます。

### オープンソースライブラリ

[ライブラリ](/opensource/index.md)は、その下で動くエンジンです。OpenAPI のパーサーとアップグレーダー、マルチプロトコル CLI、コードジェネレーター、MCP サーバー、リクエストランナー、cURL / Postman コンバーター、埋め込み可能なエディターがあります。それぞれが独立して npm に公開され、専用のインストールガイドと API リファレンスを備えています。低レベルの技術詳細はここにあります。

## あなたにとって変わること

- **クリックではなく、結果を指示します。** 目標を述べれば、アシスタントがレビュー可能な手順で作業を進めます。
- **API が最初からエージェント対応になります。** ドキュメントを生成する同じ契約が MCP ツールも生成するため、AI エージェントは初日から正しく API を呼べます。
- **ブレがありません。** 設計、デバッグ、テスト、モック、ドキュメントが 1 つのファイルを読みます。
- **すべてのプロトコルが 1 か所に。** HTTP、SSE、WebSocket、GraphQL、gRPC、MCP が 6 つのツールではなく単一の仕様に含まれます。
- **ロックインなし。** モデルを持ち込み、デスクトップでキーをローカルに保ち、リポジトリ内の平文の YAML を所有できます。
