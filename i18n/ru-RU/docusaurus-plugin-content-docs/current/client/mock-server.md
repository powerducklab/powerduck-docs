# Локальный mock-сервер

Mock-сервер создаёт работающую замену API прямо из спецификации. Это позволяет разрабатывать фронтенд и клиенты до появления бэкенда без внешней инфраструктуры. Сервер работает в основном процессе настольного приложения.

## Запуск mock-сервера

Запустить mock можно на экране mock-сервера или прямо из чата с ИИ. При запуске из чата приложение подтверждает адрес, на котором работает сервер.

Доступны следующие параметры:

| Параметр | Диапазон / формат | Назначение |
|---|---|---|
| `port` | Целое число `1`–`65535` | Локальный порт для прослушивания |
| `basePath` | Префикс пути URL | Размещает mock по базовому пути |
| `latencyMs` | `0`–`10000` | Добавляет искусственную задержку для имитации сетевой задержки |
| `overrides` | До 100 переопределений ответов | Возвращает заданные ответы для выбранных операций |

Недопустимые порты и значения задержки отклоняются с понятным сообщением, а не приводят к запуску неработающего сервера.

## Несколько mock-серверов

Можно запускать несколько mock-серверов одновременно, например по одному для каждого открытого документа. Приложение показывает запущенные серверы (`mock:list`) и позволяет остановить отдельный сервер (`mock:stop`). Каждый mock связан с идентификатором и названием документа, поэтому их легко различать.

## Просмотр полученных запросов

Mock записывает полученные запросы. Их можно просматривать (`mock:requests`) с необязательным ограничением количества и очищать список записей. Это помогает проверить, что клиент вызвал нужную операцию с ожидаемыми параметрами, даже без настоящего бэкенда.

## Переопределение ответов

Если стандартного примера или ответа, сформированного по схеме, недостаточно, можно задать конкретный ответ для отдельной операции. Число переопределений ограничено 100, чтобы конфигурация оставалась управляемой.

## Когда использовать

- Чтобы продолжить разработку фронтенда по контракту, пока бэкенд ещё создаётся;
- Чтобы воспроизвести медленную работу или пограничные случаи, изменяя задержку и ответы;
- Чтобы показать сценарий работы API без развёрнутого окружения;
- Чтобы проверить, что сгенерированные клиенты вызывают операции согласно проекту.

Mock читает ту же спецификацию, что и остальные инструменты, поэтому остаётся согласованным с контрактом при изменениях проекта.
