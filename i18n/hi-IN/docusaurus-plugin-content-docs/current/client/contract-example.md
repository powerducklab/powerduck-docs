# अनुबंध परीक्षण से इम्प्लीमेंटेशन की त्रुटि ढूँढें

यह उदाहरण डेवलपर MCP रनर का उपयोग करता है, जिसमें रिस्पॉन्स स्कीमा वैलिडेशन संस्करण 0.7.6 से उपलब्ध है। Node.js 22.12.0 या नया संस्करण चाहिए। इसमें काल्पनिक डेटा और केवल लूपबैक पर चलने वाला बैकएंड है; डिपेंडेंसी इंस्टॉल करने के बाद खाते, मॉडल या सार्वजनिक API की आवश्यकता नहीं होती।

```sh
git clone https://github.com/powerducklab/dev-mcp-server.git
cd dev-mcp-server
npm ci
npm run build
node examples/contract-total/verify.mjs
```

रिस्पॉन्स `{"total":"42"}` है, जबकि स्कीमा संख्या माँगता है। वास्तविक वैलिडेटर `/total must be number` बताता है और स्थिति कोड 1 के साथ बंद होता है।

```sh
node examples/contract-total/verify.mjs --correct
```

अब बैकएंड `{"total":42}` लौटाता है; वही जाँच पास होती है और स्थिति कोड 0 मिलता है। खुद सुधारने के लिए `examples/contract-total/server.mjs` में `total` एक्सप्रेशन बदलें ताकि वह संख्या लौटाए। त्रुटि छिपाने के लिए अनुबंध कमजोर न करें।

हर बार चलाने पर एक खाली स्थानीय पोर्ट लिया जाता है और अंत में सर्वर बंद किया जाता है। सोर्स फ़ाइलें और कमांड [उदाहरण प्रोजेक्ट](https://github.com/powerducklab/dev-mcp-server/tree/main/examples/contract-total) में हैं। फिलहाल स्कीमा जाँच JSON रिस्पॉन्स तक सीमित है; फ़ॉर्मेट वैलिडेशन या रिमोट स्कीमा लाना शामिल नहीं है। अगर असमर्थित कंटेंट टाइप में स्कीमा जाँच ज़रूरी हो, तो चुपचाप पास करने के बजाय सीमा बताई जाती है।

यह वास्तविक बैकएंड की जाँच करता है। सफल Mock रिक्वेस्ट केवल उदाहरण वर्कफ़्लो दिखाती है। चाहें तो कोडिंग एजेंट स्पष्ट `baseUrl` के साथ `run_contract_tests` चलाकर वही जाँच कर सकता है; पैच लागू करने से पहले समीक्षा करें।
