# AI와 모델

Powerduck에서는 어시스턴트 모델을 직접 선택하고 설정할 수 있습니다. 데스크톱 요청은 메인 프로세스를 거쳐 선택한 엔드포인트로 전송되며 문서 변경은 계속 검토 가능한 카드로 진행됩니다.

## 모델 가져오기

설정에서 어떤 **OpenAI 호환** Chat Completions 엔드포인트에든 어시스턴트를 구성합니다.

- 내장 제공업체 프리셋을 선택하거나 **사용자 지정** 제공업체를 정의.
- 표시 이름, 베이스 URL, API 키, 모델 ID 제공.
- 여러 프로필을 구성하고 선택 가능.

특정 제공업체에 종속되지 않습니다. 자체 호스팅 또는 외부 OpenAI 호환 엔드포인트도 같은 방식으로 연결할 수 있어 팀의 모델 사용 정책에 맞출 수 있습니다.

## 고급 기능과 우아한 폴백

각 프로필에는 **고급 기능** 옵션이 있고 기본 켜짐입니다.

- 켜면 앱이 모델의 **네이티브 함수 호출**을 사용해 도구 카탈로그를 네트워크로 보내 모델이 적절한 도구를 직접 선택해 호출하게 합니다.
- 어떤 엔드포인트가 네이티브 도구 인수를 거부하면——도구 미지원 작은 모델 등——그 엔드포인트가 기억되고 **콘텐츠 기반 폴백 프로토콜**로 한 번 재시도합니다.

대체 경로는 호환성을 높이지만 성공을 보장하지 않습니다. 네트워크, 인증, 모델 오류는 여전히 발생할 수 있습니다. 항상 기본 방식을 써야 하는 프로필에서는 고급 기능을 끄세요.

도구 작업에도 한도가 있습니다. 에이전트의 도구 라운드는 기본 세 번으로 제한되며 같은 실행에서 중복 호출을 제거합니다.

## 왜 요청을 메인 프로세스로 보내는가

데스크톱 클라이언트에서 완성 요청은 WebView가 아닌 **Node 메인 프로세스**에서 발행됩니다. 두 가지 구체적 이점이 있습니다.

- **브라우저 CORS 벽 없음.** 웹에 적용되는 크로스 오리진 제한이 모델 엔드포인트 호출을 막지 않습니다.
- **HTTP 요청은 렌더러 외부에서 실행됩니다.** 렌더러의 네트워크 패널에는 메인 프로세스의 HTTP 통신이 표시되지 않습니다. 그렇다고 프롬프트나 키가 렌더러 메모리, 로그 또는 다른 개발자 도구에 없음을 보장하지는 않습니다.

데스크톱 게이트웨이는 요청 구조를 검증하고 리소스 한도를 적용합니다.

- HTTP(S) URL만 허용하며 헤더 이름과 값, 본문 크기, 시간 제한, 동시 요청 수를 검사합니다. 로컬 및 비공개 엔드포인트도 허용됩니다. 호스트 허용 목록이나 제공업체의 개인정보 보호를 보장하는 기능은 아닙니다.
- 요청은 취소 가능합니다(`ai:cancel`).

## 데스크톱과 Web

같은 어시스턴트가 두 실행 환경에서 동작하고 각각에 맞는 경로를 씁니다.

- **데스크톱(Electron):** 능력이 로컬로 import되어 실행되고 완성 요청이 메인 프로세스로 프록시됩니다.
- **Web:** 같은 워크플로가 HTTP로 실행되고 로컬 모듈이 아닌 서비스 API를 호출합니다.

이것이 앱이 Electron 경로에 더해 Web 호환 경로를 유지하는 이유입니다. 의도 처리와 카드 표현은 일치하고 전송만 실행 환경에 따라 바뀝니다.

## 의도 식별 방식

의도는 기능마다 키워드를 나열해 처리되지 않습니다. 대신 앱은 명확하고 잘 설명된 **도구 카탈로그**를 모델에 제시합니다——각 도구의 ID, 인수, 어떤 정확한 상황에서 쓰는지. 모델이 카탈로그에서 최적 도구를 선택하고 결정론적 호스트가 검증해 실행하며 쓰기 작업은 확인을 요청합니다.

그래서 기능 추가는 더 긴 키워드 목록 유지가 아니라 카탈로그에 도구 추가(와 정확한 기술)를 의미합니다. 같은 카탈로그는 MCP 서버를 통해 외부 에이전트와 공유돼 제품과 다른 도구 간 능력이 정렬됩니다.

## 프라이버시 자세

- 프롬프트, 선택한 컨텍스트, 도구 설명, 인증 정보는 설정한 모델 엔드포인트로 전송됩니다. 호스팅 제공업체는 이 데이터를 받습니다. 정책상 로컬 추론이 필요하면 신뢰할 수 있는 로컬 엔드포인트를 사용하세요.
- 각 변경을 검증해 적용하는 것은 모델이 아닌 결정론적 호스트입니다.
- 모든 쓰기는 실행 전 당신의 승인을 받습니다.
