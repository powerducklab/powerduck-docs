# 사용자 지정 도메인

기본으로 문서는 Powerduck 공유 주소에서 제공됩니다. 사용자 지정 도메인은 공유 링크가 아닌 **자신의 호스트 이름**으로 문서와 MCP를 표시해 브랜드로 API를 게시하는 데 중요합니다.

사용자 지정 도메인은 유료 기능으로 **Pro와 Team** 플랜에서 사용 가능합니다(`oas.custom_domain` 권한으로 확인).

## 호스트 전체 묶기와 하위 경로 묶기

묶기는 다음을 대상으로 합니다.

- **호스트 전체**——`api.example.com`이 루트에서 한 문서 제공.
- **호스트와 하위 경로**——`example.com/v1`이 `/v1` 아래 한 문서 제공.

하위 경로 묶기로 한 호스트 이름이 여러 문서를 제공할 수 있습니다.

```text
example.com/v1  -> document A
example.com/v2  -> document B
```

이로써 문서마다 한 호스트 이름만 쓰는 제한을 피하고 버전 붙은 베이스 경로를 지원합니다.

## 사용자 지정 도메인에서

공유 주소에서 쓸 수 있는 같은 모드가 묶인 도메인 아래 짧고 안정된 경로로 제공됩니다.

| 모드 | 호스트 전체 | 하위 경로 |
|---|---|---|
| 현재 스펙 | `/oas` | `/v1/oas` |
| 버전 고정 스펙 | `/v/:version/oas` | `/v1/v/:version/oas` |
| MCP | `/mcp` | `/v1/mcp` |

호스트는 요청 호스트 이름과 경로에서 해결해 묶인 문서로 라우팅합니다. 이 경로들은 CORS 사전 점검을 처리합니다.

## 도메인 추가 및 검증

소유권 검증 전 도메인이 신뢰되지 않아 흐름이 명확합니다.

1. 문서에 호스트 이름(또는 호스트 이름과 경로) **추가**.
2. 서비스가 묶기와 **DNS 지시** 반환.
3. DNS 기록 만들고 **검증**.
4. 묶기가 대기에서 검증됨으로 바뀌고 제공 시작.

소유권 확인은 **TXT 기록**을 씁니다.

| 필드 | 값 |
|---|---|
| 기록 유형 | `TXT` |
| 호스트 | `_powerduck-challenge.<your-domain>` |
| 값 | `powerduck-verify=<verification-token>` |

검증은 DNS에서 TXT 기록을 읽고 상수 시간 일치로 토큰을 비교합니다. 검증된 묶기는 검증된 채 유지돼 재확인 불필요.

### 예

`api.example.com`을 위해 TXT 기록 추가.

```text
_powerduck-challenge.api.example.com
TXT "powerduck-verify=<the-token-shown-for-the-binding>"
```

이후 문서 워크스페이스에서 **검증** 선택. 검증됨으로 보고되면 문서와 MCP가 그 도메인에서 제공됩니다(문서 활성, 각 모드 활성 전제).

## 묶기 관리

- 문서에 묶인 도메인 **목록**. 상태와 베이스 경로 포함.
- DNS 기록 추가 후 대기 묶기 **검증**.
- 묶기 **삭제**로 그 도메인 제공 중지.

접근 표시 변경은 캐시된 호스트 해석을 무효화해 갱신이 즉시 반영되고 낡은 묶기를 제공하지 않습니다.

## 접근 통제는 계속 적용

사용자 지정 도메인은 추가 주소지 우회가 아닙니다. 같은 관문이 적용됩니다.

- 문서는 `ACTIVE`여야 함.
- 문서와 MCP에 각 활성 표시.
- 보기 비밀번호가 문서를, MCP 접근 키가 MCP를 계속 보호.

[접근 통제](/docs/cloud/access-control)를 보세요.
