# 本地 Mock 服务器

Mock 服务器直接根据规范为你的 API 提供一个可用的替身，因此前端和客户端工作可以在后端就绪前推进——也无需搭建外部基础设施。它运行在桌面主进程中。

## 启动 Mock

你可以从 Mock 服务器形态或直接从 AI 对话启动 Mock。从对话启动时，应用会确认它提供服务的地址。

以下选项可用：

| 选项 | 范围/形态 | 用途 |
|---|---|---|
| `port` | 整数 `1`–`65535` | 监听的本地端口 |
| `basePath` | URL 路径前缀 | 在某个基础路径下提供 Mock |
| `latencyMs` | `0`–`10000` | 添加人为延迟以模拟网络时延 |
| `overrides` | 最多 100 条响应覆盖 | 为选定操作返回特定响应 |

无效的端口或延迟值会以清晰信息被拒绝，而不是启动一个坏掉的服务器。

## 多个 Mock

你可以同时运行多个 Mock——例如每个打开的文档一个。应用会列出运行中的 Mock（`mock:list`），并可停止单个 Mock（`mock:stop`）。每个 Mock 都关联一个文档 ID 和名称，让它们保持可区分。

## 检查收到的请求

Mock 会记录它收到的请求。你可以查询它们（`mock:requests`，可选数量限制），并清空记录。即使没有真实后端，这也有助于确认客户端是否以预期参数调用了正确的操作。

## 响应覆盖

当默认示例或由模式推导的响应不够时，响应覆盖可让某个特定操作返回选定的响应。覆盖有上限（最多 100 条），以保持配置可预测。

## 何时使用

- 针对仍在构建的契约，解除前端开发的阻塞；
- 通过调整延迟和响应，复现慢速或边缘情形；
- 在没有已部署环境的情况下演示 API 流程；
- 验证生成的客户端是否按设计调用操作。

Mock 与其他每个形态读取同一份规范，因此当设计变化时它始终与契约对齐。
