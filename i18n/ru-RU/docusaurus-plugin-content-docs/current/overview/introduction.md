# Введение

Подход к созданию API меняется. Два десятилетия **оператором** был человек, нажимающий кнопки в графическом интерфейсе, а **потребителем контракта API** — человек, читающий документацию. Теперь меняются обе стороны:

- Оператором всё чаще становится **ИИ-ассистент**, который превращает намерение в действие;
- Потребителем всё чаще становится **ИИ-агент**, вызывающий API как инструмент через MCP.

Инструменты предыдущей эпохи — API-клиент, просмотрщик спецификаций, коллекция запросов — создавались для человека за клавиатурой. Powerduck создан для новых условий. Это не просто более удобный API-клиент или более красивый просмотрщик, а **платформа со встроенным ИИ, в основе которой лежит один файл OpenAPI**.

## Основа: один локальный файл OpenAPI

Всё начинается с обычного `openapi.yaml` в вашем репозитории: открытого файла под контролем версий, понятного и человеку, и ИИ. Не с закрытой базы данных и не с облачной учётной записи.

```text
                one local openapi.yaml
                         |
      you + AI -> design debug test mock docs data-model
                         |
                      MCP tools
                         |
               any AI coding agent
```

Этот файл и есть контракт. Все рабочие процессы читают его; тот же файл можно передать любому ИИ-агенту для программирования через MCP. Поэтому вы, встроенный ассистент и внешние агенты используют единый источник истины. Когда проектирование, отладка, тесты, моки и документация опираются на один файл, синхронизация инструментов перестаёт быть отдельной задачей. Это следствие архитектуры.

Powerduck работает с OpenAPI 3.2 и читает существующие документы 3.0 и 3.1, а также Swagger 2.0, обновляя их на месте. API, не основанные на HTTP, — SSE, WebSocket, GraphQL, gRPC и MCP — описываются обычными элементами путей с помощью расширения `x-protocol`, без принудительного приведения к структуре, рассчитанной только на REST.

## Работа с ИИ

- Откройте YAML, и ассистент сразу предложит возможные действия;
- Опишите результат обычным языком: «создай эндпоинты заказов», «подготовь тестовые данные», «запусти сценарий оформления заказа и составь отчёт». Ассистент выберет нужный инструмент и предложит изменение;
- Каждое изменение появляется в виде **карточки для проверки** и применяется только после вашего одобрения;
- Когда вы дорабатываете конкретный API, ассистент остаётся в его пределах и меняет только то, что вы попросили, не затрагивая остальные части документа;
- Локальные файлы остаются на диске. Удалённый ИИ отправляет нужный контекст настроенному вами сервису моделей с его учётными данными. Публикация в Cloud загружает выбранное содержимое. Необязательная статистика использования по умолчанию отключена и управляется отдельно; для локальной работы учётная запись не нужна.

## Приоритет локальной работы

Powerduck запускается на вашем компьютере, открывает и сохраняет реальные файлы, работает без интернета и хранит ключи API и запросы к ИИ вне браузера. Облако — необязательное дополнение для совместного доступа и публикации, а не условие начала работы.

## Три способа использовать Powerduck

| Продукт | Что это | Для чего подходит |
|---|---|---|
| [**Настольный клиент**](/docs/ru-RU/client/introduction/) | Приложение Electron с приоритетом локальной работы, ИИ-ассистентом и полноценной средой для API | Для разработчиков, которые хотят работать на своём компьютере, в том числе без интернета, и хранить ключи и запросы к ИИ локально |
| [**Powerduck Cloud**](/docs/ru-RU/cloud/introduction/) | Сервис размещения OAS, онлайн-документации и управляемого MCP | Для обмена API, публикации постоянных ссылок и предоставления MCP без запуска собственного сервера |
| [**Открытые библиотеки**](/docs/ru-RU/opensource/) | Совместимые npm-пакеты `@powerduck/*`, которые можно комбинировать | Для собственных инструментов, конвейеров CI и встраиваемых компонентов |

Все три продукта используют одни и те же движки. Настольный клиент и облако построены на открытых библиотеках, поэтому возможности работают одинаково при локальном запуске, вызове по сети или непосредственном импорте пакета.

### Настольный клиент

[Настольный клиент](/docs/ru-RU/client/introduction/) полностью работает на вашем компьютере. Он открывает и редактирует файлы на диске, отправляет запросы через локальный процесс, запускает локальный мок и не выводит запросы к ИИ и ключи API в консоль браузера. Вы самостоятельно выбираете и настраиваете модель. Каждое предложенное изменение сначала показывается в карточке для проверки.

### Powerduck Cloud

[Powerduck Cloud](/docs/ru-RU/cloud/introduction/) переносит тот же рабочий процесс в онлайн. Добавьте файл, репозиторий Git или URL, выберите операции, которые нужно предоставить, и получите постоянные ссылки на документацию и управляемый эндпоинт MCP. Доступ можно защитить паролем просмотра или ключом доступа MCP. Платные планы добавляют синхронизацию с Git, собственные домены и повышенные лимиты.

### Открытые библиотеки

[Библиотеки](/docs/ru-RU/opensource/) — это движки в основе продукта: парсер и средство обновления OpenAPI, многопротокольный CLI, генератор кода, сервер MCP, исполнитель запросов, конвертеры cURL и Postman, а также встраиваемые редакторы. Каждая библиотека публикуется в npm отдельно и имеет собственное руководство по установке и справочник API. Здесь находятся подробные технические сведения.

## Что меняется для вас

- **Вы задаёте результат, а не последовательность нажатий.** Опишите цель, и ассистент выполнит работу через шаги, которые можно проверить.
- **API готовы к работе с агентами.** Один контракт создаёт и документацию, и инструменты MCP, поэтому ИИ-агенты могут корректно вызывать API с самого начала.
- **Всё остаётся согласованным.** Проектирование, отладка, тесты, моки и документация читают один файл.
- **Все протоколы в одном месте.** HTTP, SSE, WebSocket, GraphQL, gRPC и MCP описываются одной спецификацией вместо шести отдельных инструментов.
- **Нет привязки к поставщику.** Выберите свою модель, храните ключи локально в настольном приложении и сохраняйте контроль над YAML в репозитории.
