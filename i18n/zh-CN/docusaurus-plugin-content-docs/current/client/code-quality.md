# 代码质量

登录桌面客户端后，从侧栏打开“代码质量 · AI Review”，选择项目目录和入口文件，再开始 AI 扫描。扫描优先处理入口及其相对依赖，随后检查其余文件。当前依赖解析支持 JavaScript/TypeScript 相对导入；其他源代码语言使用源码、测试和项目清单上下文，不声称已构建完整调用图。

## 有证据的审查

每条问题包含 P0–P3 优先级、文件相对路径、原始行号、类别、置信度、证据及修复提示词。点击位置可高亮源码对应行。P0 为立即造成严重后果的问题，P1 为高影响问题，P2 为一般缺陷，P3 为改进建议。

审查关注输入到危险操作的数据流、权限边界、错误传播、取消与清理、并发一致性、无界计算、资源占用和测试断言。看不到的调用方必须保留为假设，不应作为确定缺陷。审查本身不修改业务代码；复制修复任务交给其他代码 Agent，或在 AI Chat 中继续讨论。

## 融入现有项目的测试

“测试评估”结合项目清单、现有测试框架、导入和 fixtures，分析缺失的边界与失败用例。点击“生成测试草案”后先查看完整代码，再确认需要创建的文件。桌面端会再次展示文件列表供用户确认；取消后保留草案。

只允许创建项目内的新测试文件，不覆盖已有文件，不越过目录边界，不自动执行测试。生成代码仍需用项目自己的测试命令验证，可以明确要求其他代码 Agent 完成验证。文件数量不能代替真实覆盖率，源码分析不代表测试已通过。

## 迭代变更

点击“更新变更”，将当前代码与上次快照比较，展示新增、修改、删除文件及只读代码差异。重新打开此前选过的项目也会记录相对上次保存快照的变更。本地保存最近 20 次有变化的快照。

这是快照历史：两次记录之间的修改会合并显示，并不声称记录了每一次按键或每一个 Git 提交。

## AI Chat 继承全部能力

`quality.choose_project`、`quality.review`、`quality.results`、`quality.propose_tests`、`quality.create_tests`、`quality.refresh` 和 `quality.changes` 与可视化页面共享项目及结果。AI 分析和测试建议使用同一账户额度；从 Chat 创建文件也必须经过桌面确认。

## 范围和数据

读取器排除依赖、构建目录、隐藏文件、符号链接及常见凭据文件名；最多读取 1,000 个文件、共 4 MB、单文件 200 KB。页面列出超限文件和实际已分析数量，不完整扫描不能被当成全项目结论。

选定源码上下文会发送给平台配置的模型供应商。文件名过滤不能保证代码不含敏感信息，应只选择允许发送给供应商的内容。扫描不执行项目命令或依赖，也不构成安全认证。
